ADD & PUBLISH HTML TOOLS

One home for every new tool.

This library is a static website. Public tools are bundled into the catalog and published together. Personal browser imports are separate and do not upload to the public collection.

1. Add a tool to the catalog

From the project folder, run the helper below. The source can be one self-contained HTML file or a directory with index.html and its local CSS/JavaScript assets. Use a unique ID. The script copies the files, adds a catalog entry and rebuilds the website.

python scripts/add_tool.py /path/to/my-tool.html   --id wave-lab --title "Wave Lab"   --description "Explore wave properties interactively."   --category Physics --level "AS & A Level"

Update an existing tool by editing its files under tools/<id>/ and its metadata in site-assets/catalog.js, then rebuild. Do not enter passwords or API keys in browser tools.

2. Build and test

npm test
python scripts/build_site.py
python tests/site_test.py
python3 -m http.server 8000 --directory dist

Optional browser tests use Python Playwright and system Chromium: run python tests/site_browser_test.py and python tests/browser_test.py. No npm packages are needed to build or run the site. The build creates dist/, the deployable website, and standalone HTML downloads.

For standalone downloads, use ordinary local scripts and styles with double-quoted paths. Keep tools self-contained where possible. Dynamic imports, remote APIs and assets loaded at runtime need tool-specific bundling and offline testing before publication.

3. Publish with GitHub Pages

  1. Push the source to the repository’s main branch.
  2. In the repository, open Settings → Pages → Build and deployment → Source → GitHub Actions. You need repository administrator access.
  3. The included Publish Learning Lab workflow tests and builds the site, then deploys the dist folder. Run it manually under Actions if needed.
  4. Open the public address reported by the deployment. Confirm a tool and its download work there.

After initial Pages setup, pushing new tools to main updates the same website. GitHub Pages availability depends on repository visibility and account plan. A workflow file alone does not mean a site is live.

Alternative static hosts

Upload the contents of dist/ to any static web host, or drag the folder into your hosting provider’s static-site upload interface. No database, server application or build service is needed to run the published files. Keep the directory structure intact.

Who can upload?

Repository maintainers publish public tools through Git and authenticated hosting. Visitors may import personal HTML files into their own browser. This site intentionally has no public server upload endpoint or shared student database. Keep private student information out of the public catalog.
